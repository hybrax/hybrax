hybrax.train.harness¶

The training and forward-evaluation harness: the layer above trainer.py’s single batch step.

This module provides:

  • train_collection / train_from_collection / train_from_prepared_json — train one reaction/loss module pair over a batch stream, at increasing levels of convenience (a prepared store, a raw collection, a prepared JSON file on disk).

  • model_predict / forward_from_collection / evaluate_trained_wrapper — run a trained model forward over new or held-out data, without touching the optimizer.

  • prepare_training / prepare_training_from_runtime_artifact / train_harness_config_from_run_config — build every hook-visible object (reaction module, loss module, optimizer, harness config) from a RunConfig and a runtime artifact, the path the CLI and LOO folds both go through.

Batching, the JIT-compiled train step, and per-sample loss evaluation live in trainer.py; this module owns everything around that step — process selection, checkpointing, logging, and the public entry points.

hybrax.train.harness.forward_from_collection(collection, *, model_path, config=None, custom_py=None, training_process_names=None, run_config=None, custom_module=None, prediction_process_names=None, prediction_grid_n=200)[source]¶

Run one forward pass per selected process of collection.

collection is evaluation data only. The model itself is rebuilt from the prepared collection it trained on: that input is resolved from model_path’s run directory and its recorded inputs.prepared_input.content_hash is verified before any hook runs (see reconstruct_training()). So the reaction module, the loss module, every SCALE_* and the deserialisation template are exactly training’s, and evaluation data never reaches a constructor hook.

A separate store is built from collection for the solves. It must be compatible with the training data — same measured/modeled variables in the same order — or the call fails with an explicit error.

Parameters:

  • collection (hybrax.format.dataclasses.BioProcessCollection) – Evaluation-only process collection to forward-solve.

  • model_path (str | pathlib.Path) – Path to the trained model’s run/checkpoint directory.

  • config (ForwardConfig | None) – Forward-run settings (prediction scope, plotting), or None for defaults.

  • custom_py (str | pathlib.Path | None) – Override for the recorded custom.py path, or None to use the one the run recorded.

  • training_process_names (tuple[str, ...] | None) – Restrict reconstruction to this subset of the model’s original training processes, or None for all of them.

  • run_config (hybrax.train.run_config.RunConfig | None) – Pre-loaded run config, or None to read it from model_path’s config.json.

  • custom_module (Any | None) – Pre-loaded custom module, or None to load it from custom_py/the recorded path.

  • prediction_process_names (tuple[str, ...] | None) – Restrict prediction to this subset of collection’s processes, or None for all of them.

  • prediction_grid_n (int) – Size of the evenly-spaced prediction grid; see model_predict()’s grid_n.

Returns:

per-process dense exports plus the rebuilt wrapper and config.

Return type:

The forward result

Raises:

ValueError – If collection’s measured/modeled variables are incompatible with the training data.

hybrax.train.harness.model_predict(trained_wrapper, config, collection, *, process_names=None, grid_n=200)[source]¶

Forward-solve a trained model over collection in one batched solve.

The companion to model_load(): pass the pair it returned plus the collection you want predictions for. Solver settings come from config.solver — the values the model was actually fitted under — so there is nothing to re-decide here.

collection may hold processes the model never trained on. Every process in a collection shares one RhsOde layout; only controls and events differ, and a mismatch fails fast via validate_rhs_ode_compatibility().

To predict a subset, pass process_names — do not slice collection.processes. The hybrax.train metadata block carries its own process_order, so a hand-sliced collection fails when the controls store is rebuilt.

process_names defaults to every process in collection. grid_n is the size of the evenly-spaced output grid; each process’s own measurement times are spliced into it, so the returned t is that union (sorted, and therefore usually a little longer than grid_n) — a node lands exactly on every measurement instead of interpolating across bolus/feed discontinuities.

Two requirements on collection, both structural rather than incidental:

  • Every process needs a measurement at its first time for every target — that is where the ODE initial condition comes from.

  • The target set must match what the model was trained on (config.data.targets).

Returns {process_name: DenseProcessExport}. Losses are deliberately not returned: they are meaningless for a process whose measurements are only a t0 seed. Use evaluate_trained_wrapper() when you want them.

Note

This reuses trained_wrapper’s SCALE_* as-is and never rebuilds the reaction module. forward_from_collection() rebuilds them, but always from the model’s own recorded training input, so it does not re-scale the model against the collection it is asked to evaluate either.

Parameters:

  • trained_wrapper (hybrax.train.wrapper.HybridOdeWrapper)

  • config (hybrax.train.run_config.RunConfig)

  • collection (hybrax.format.dataclasses.BioProcessCollection)

  • process_names (tuple[str, ...] | None)

  • grid_n (int)

Return type:

dict[str, hybrax.train.postprocessing.DenseProcessExport]

hybrax.train.harness.train_collection(store, *, reaction_module, loss_module=None, config=None, optimizer=None)[source]¶

Train one reaction module over one or many processes from one store.

Scales live on reaction_module; loss terms are produced by loss_module (both attached to the wrapper, partitioned together). When loss_module is None, the default per-target MSE module is used. optimizer, when provided (via the build_optimizer hook), fully owns optimizer construction; otherwise the default _build_optimizer chain is used.

Parameters:

  • store (hybrax.train.training_data.TrainingDataStore) – Prepared training data for every candidate process.

  • reaction_module (hybrax.train.model_api.UserReactionModule) – Reaction module to train.

  • loss_module (hybrax.train.model_api.UserLossModule | None) – Loss module to train alongside it, or None for the default per-target MSE module.

  • config (TrainHarnessConfig | None) – Harness settings (batching, optimizer, solver, checkpointing, logging), or None for defaults.

  • optimizer (optax.GradientTransformation | None) – Pre-built optimizer, or None to use the default chain.

Returns:

The trained wrapper plus the full per-step training history.

Raises:

ValueError – If reaction_module has a nonzero latent state without config.allow_stateful_models, or config’s solver settings are non-positive.

Return type:

TrainHarnessResult
