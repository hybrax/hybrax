A Gaussian-process model¶

Demonstrates. A sparse Gaussian process, mean and variance both, occupying the reaction module’s slot instead of a neural network, trained end to end by hybrax.train’s own optimizer, with the predictive uncertainty read out through ReactionOutputs.auxiliary.

Inspired by Helleckes et al. 2024 [1], who fit a GP-based hybrid model for bioprocess rates. This page is not a replication: their GP is fit by maximum-likelihood estimation on a precomputed rate target, ours is trained by gradient descent through the continuous ODE solve, which is hybrax.train’s own training loop and nothing else. The mechanism (an SE kernel with automatic relevance determination, predicting a rate from the current state) is the same; how it gets fit is not. See Knowledge transfer for the paper’s other headline result, pooling data across products, reproduced the same way.

The walkthrough below shows the file in pieces, next to the reasoning for each one. For the whole thing at once: to copy, diff against your own, or just read top to bottom:

Full custom.py
  1"""A Gaussian-process reaction module.
  2
  3A closed-form sparse-GP posterior (mean AND variance, via a Cholesky solve
  4over a small set of trainable inducing points) occupies the same slot a
  5neural network normally would. Trained end-to-end by hybrax.train's own gradient
  6descent through the whole trajectory, unlike a standard GP's marginal-
  7likelihood fit: see the page for exactly how these differ, and why.
  8
  9The predictive variance goes into ``ReactionOutputs.auxiliary``, which
 10hybrax.train threads straight into ``predictions.csv`` (see ``estimate_all_scales``
 11below for the rest: verbatim from Tutorial 4).
 12"""

 28class GPReactionModule(UserReactionModule):
 29    centers: jax.Array = trainable_field()  # Z, (n_inducing, n_features)
 30    log_lengthscale: jax.Array = trainable_field()  # (n_features,), ARD
 31    log_output_scale: jax.Array = trainable_field()  # scalar kernel amplitude
 32    log_noise: jax.Array = trainable_field()  # scalar jitter
 33    pseudo_targets: jax.Array = trainable_field()  # y, (n_inducing, n_rates)
 34
 35    def __init__(self, *, key, n_inducing=12, **scale_kwargs):
 36        super().__init__(**scale_kwargs)
 37        n_features = self.n_modeled_RMCs
 38        n_rates = self.n_modeled_BiologicalOde_rates
 39        key_c, key_y = jax.random.split(key)
 40        self.centers = jax.random.normal(key_c, (n_inducing, n_features))
 41        self.log_lengthscale = jnp.zeros(n_features)
 42        self.log_output_scale = jnp.array(0.0)
 43        self.log_noise = jnp.array(-2.0)
 44        self.pseudo_targets = jax.random.normal(key_y, (n_inducing, n_rates)) * 0.1
 45
 46    def _kernel(self, a, b):
 47        diff = (a[:, None, :] - b[None, :, :]) / jnp.exp(self.log_lengthscale)
 48        sq_dist = jnp.sum(diff**2, axis=-1)
 49        return jnp.exp(self.log_output_scale) * jnp.exp(-0.5 * sq_dist)
 50
 51    def __call__(self, t, inputs: ReactionInputs) -> ReactionOutputs:
 52        del t
 53        x = inputs.SCL_modeled_RMCs[None, :]
 54        k_zz = self._kernel(self.centers, self.centers)
 55        k_zz = k_zz + jnp.exp(self.log_noise) * jnp.eye(self.centers.shape[0])
 56        k_xz = self._kernel(x, self.centers)
 57        chol = jsl.cho_factor(k_zz, lower=True)
 58        mean = (k_xz @ jsl.cho_solve(chol, self.pseudo_targets))[0]
 59        v = jsl.cho_solve(chol, k_xz[0])
 60        var = jnp.exp(self.log_output_scale) - k_xz[0] @ v
 61        rate_std = jnp.sqrt(jnp.clip(var, 1e-12)) * jnp.ones_like(mean)
 62        return ReactionOutputs(
 63            SCL_modeled_BiologicalOde_rates=mean,
 64            SCL_modeled_Outflows_rates=jnp.zeros(0),
 65            SCL_modeled_Inflows_rates=jnp.zeros(0),
 66            auxiliary={"rate_std": rate_std},
 67        )
 68

 70def build_reaction_module(*, seed, **kwargs):
 71    scale_kwargs = {k: v for k, v in kwargs.items() if k.startswith("SCALE_")}
 72    return GPReactionModule(key=jax.random.key(seed), **scale_kwargs)

 80    def max_abs_state(name):

 86        return max(best, 1e-6)
 87
 88    rmc_scale = {name: max_abs_state(name) for name in rhs.name_modeled_RMCs}

 90    def rate_scale_for(species):
 91        per_process = []
 92        for i in range(n_processes):
 93            c_times, c_values = runtime_data.raw_state_trace(i, species)
 94            x_times, x_values = runtime_data.raw_state_trace(i, "biomass")
 95            exposure = np.trapezoid(x_values, x_times)
 96            per_process.append(abs(c_values[-1] - c_values[0]) / max(exposure, 1e-9))
 97        return max(max(per_process), 1e-9)

105        SCALE_V_in_cumulative=jnp.asarray(
106            max(runtime_data.initial_volume(i) for i in range(n_processes))
107        ),
108        SCALE_modeled_Inflows_cumulative=empty,
109        SCALE_modeled_Inflows_rates=empty,
110        SCALE_modeled_Outflows_cumulative=empty,
111        SCALE_modeled_Outflows_rates=empty,

113        SCALE_controlled_Inflows_rates=empty,
114        SCALE_controlled_Outflows_cumulative=empty,
115        SCALE_controlled_Outflows_rates=empty,
116        SCALE_controlled_PVs=empty,
117        SCALE_controlled_Inflows_Cin=jnp.maximum(
118            jnp.abs(jnp.asarray(rhs.Cin_controlled_Inflows)), 1.0
119        ),

The kernel¶

A squared-exponential kernel with automatic relevance determination (ARD): one lengthscale per input feature, so the module can learn that some state axes matter more than others to “how similar are these two states.”

centers are the inducing points (Z in the usual GP notation): trainable locations in state space, not a subsample of real data. pseudo_targets are their corresponding outputs (y). Both start random and move under gradient descent, same as any other trainable_field().

jax.scipy.linalg.cho_factor/cho_solve over the n_inducing × n_inducing kernel matrix gives a real closed-form GP posterior: mean is the predictive mean (what gets returned as the rate), var is the predictive variance at the current state. This is not an RBF network only mimicking a GP’s mean, it is the actual posterior computation, just fit by a different procedure than a textbook GP.

The predictive std goes straight into auxiliary, which hybrax.train threads into predictions.csv as extra columns: no new plumbing needed.

The GP’s inductive bias, smoothness via the kernel, is a reasonable prior here: the R² values above are what that prior achieves against this page’s own data, which is the question this page sets out to answer.

Left column: measured points against the integrated trajectory. Right column: the rates the GP actually predicted along the way, q_biomass/q_glucose/q_product, which never enter the loss directly, only their integral does.

What the GP actually learned¶

centers: spread (std) per feature = [0.91912208 0.81590832 0.7428873 ]
lengthscale (exp)   = [0.87310512 0.40858992 1.08815573]
output_scale (exp)  = 2.752
noise (exp)         = 0.049

The inducing points spread across the trajectory’s real state range rather than collapsing to a point or exploding: a degenerate fit would show up here as a near-zero or enormous spread. Lengthscales that stay the same order of magnitude as the state itself (roughly 1, since states are in SCL space) mean the kernel is using genuine spatial structure, not memorizing individual points (lengthscale near zero) or ignoring the input entirely (lengthscale huge).

Reading out the uncertainty¶

aux_rate_std_0/1/2 are ReactionOutputs.auxiliary["rate_std"], one column per rate, written out with no extra code on top of what every other page already does. All three bands are identical width at a given timestep: the kernel is shared across every rate output, so only pseudo_targets differs between them, meaning the predictive variance does not either. That is a real simplification, not a bug: an independent kernel per rate is a natural next step, not built here. The band narrows noticeably over the trajectory here, roughly halving between t=0 and the final measurement: a real signal from the closed-form posterior, not a fixed constant dressed up as uncertainty.

Gotchas¶

  • The kernel is shared across all rate outputs. rate_std is one number per timestep, not one per rate: read it as “how confident is the model here,” not “how confident is the model about this specific rate.”

  • n_inducing is a capacity knob, exactly like a network’s width. Too few and the GP cannot represent the trajectory; too many and every training step pays for an n_inducing × n_inducing Cholesky factorization it does not need.

  • No marginal-likelihood-fit hyperparameters here. log_lengthscale, log_output_scale, log_noise are just more trainable leaves, moved by the same Adam step as everything else. A textbook GP fits these by maximizing the marginal likelihood directly; this one never computes that quantity.
