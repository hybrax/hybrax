# Analytical Rate Inversion from `RhsOde`

Specification for the planned `build_rates_func_analytical` — the
sympy-driven, JIT-compilable rate-inversion path that operates on the
post-refactor [`RhsOde`](../bp_format/mechanistic.py) (i.e. on a
`BioProcess` whose [`biological_ode`](../bp_format/dataclasses.py) block
is set, either user-supplied or auto-generated by
`BioProcess.__post_init__`).

> Status: **out of scope** for the current refactor. This document
> remains the design contract; implementation is a follow-up against the
> cleaned-up surface (`ProcessOrdering` + `RhsOde` with `name_*` tuples
> and the `(c, rates, u, f_modeled_FVCs, f_modeled_SVCs)` call signature).

The legacy auto-RHS-shape spline inversion helpers (`build_q_func`,
`build_rates_func`, `estimate_specific_rates`, `integrate_process_pseudospace`)
were removed in the P3 refactor; their full behavior is preserved in
[Section 10](#10-legacy-auto-path-inversion-deleted-in-p3-refactor) for
reference. `build_rates_func_analytical` is the forward-going replacement.

## 1. Goal

Given

- a process with a `biological_ode` block declaring `algebraic`, `rates`,
  and per-state biological derivative expressions, and
- splines that reconstruct each non-volume state trajectory from data,

produce a callable

```python
rates_func(t) -> jnp.ndarray  # shape (len(name_modeled_rates),)
```

that returns the values of the user-declared rate symbols at time `t`,
ordered as in `mb.name_modeled_rates`.

The mapping is purely *inversion*: spline-implied biological `dc/dt` →
algebraic solve for the rate vector.

## 2. Inputs

| arg | type | role |
|---|---|---|
| `process` | `BioProcess` | must have `biological_ode is not None` |
| `ctrl` | `ControlSplines` | evaluates controlled-PV symbols at `t` |
| `mb` | `RhsOde` | provides ordering of states / rates / algebraic / controlled PVs |
| `state_splines` | `Dict[str, spline]` (optional) | reactor entries should be `BacktransformSpline`; built via `build_state_splines(process, ordering)` when omitted |

Output: `Callable[[float], jnp.ndarray]` of shape `(len(mb.name_modeled_rates),)`.

## 3. Mathematical model

### 3.1 Per-state biological RHS

For each non-volume state `s` (reactor-component or process-variable), the
user supplies a biological-RHS expression

```
f_s(c_state, u_ctrl, d(c_state, u_ctrl, rates), rates)
```

over the symbol table

```
{state names} ∪ {controlled-PV names} ∪ {algebraic names} ∪ {rate names}
```

where `d` is the vector of `algebraic` quantities (acyclic, recomputed every
call). After topo-sorting `algebraic` and inlining every entry into the
state derivatives, each per-state expression depends only on
`(c_state, u_ctrl, rates)`:

```
f_s(c_state, u_ctrl, rates)
```

### 3.2 Linearity requirement

`build_rates_func_analytical` requires that every per-state expression be
**linear** in the declared rate symbols. After inlining `algebraic`, each
must factor as

```
f_s(c_state, u_ctrl, rates) =
    Σ_k A_{s,k}(c_state, u_ctrl) · rate_k  +  b0_s(c_state, u_ctrl)
```

This is verified symbolically:

```
A_row = [sympy.diff(expr, rate_k) for rate_k in rate_syms]
b0    = expr.subs({rate_k: 0 for rate_k in rate_syms})
residual = sympy.expand(expr - Σ_k A_row[k]·rate_k - b0)
assert residual == 0   # else: ValueError("... non-linear in rates ...")
```

Non-linearity (rate products, rate-rate divisions, transcendental functions
of rates, etc.) raises `ValueError` at build time.

### 3.3 Biological `dc/dt` observation from splines

The inversion is performed in **pseudo-batch (`c*`) coordinates** for reactor
components — the `c*` transform absorbs feed/dilution exactly, so the
biological `dc/dt` is recovered without recomputing `Cin`, `V`, `u_flow`,
or sample/feed terms inside the inversion:

- **reactor state with `BacktransformSpline`** (carries `c_star_spline`,
  `adf_times`, `adf_values`):

  ```
  dc/dt_biol(t) = (dc*/dt)(t) / adf(t)        # adf clamped to ≥1e-12
  ```

  where `adf(t) = jnp.interp(t, adf_times, adf_values)` is the accumulated
  dilution factor used during the original pseudo-batch transform.

- **reactor state without `c_star_spline`** (fallback): the spline is
  treated as already living in the biological coordinate, i.e.

  ```
  dc/dt_biol(t) = spline.derivative()(t)      # identity transform
  ```

  This is correct only when `adf ≡ 1` (no dilution); the function does not
  warn but the result is wrong otherwise.

- **process-variable state**: identity transform.

  ```
  dc/dt_biol(t) = spline.derivative()(t)
  ```

### 3.4 Linear inversion

Stack the per-state observations into `bio_dc ∈ R^{n_state}` and the
intercepts into `b0 ∈ R^{n_state}`. Define `b = bio_dc - b0`. Then

```
A · rates = b
```

Two solve paths:

1. **Diagonal fast path** — when there are `n_rates` rate symbols and each
   one appears in exactly one row (and each such row is unique), the system
   is permuted-diagonal and is solved per-row:

   ```
   rate_k = b[row(k)] / A[row(k), k]
   ```

   No `jnp.linalg.solve` call.

2. **Square dense solve** — otherwise the inversion is restricted to the
   set of rows that constrain at least one rate (`nonzero_rows`). The
   system must be square: `len(nonzero_rows) == n_rates`. Solve

   ```
   rates = jnp.linalg.solve(A[nonzero_rows, :], b[nonzero_rows])
   ```

   If `len(nonzero_rows) != n_rates` and the diagonal fast path was not
   matched, build raises:

   ```
   ValueError(f"biological_ode has {n_rates} rate symbols but
               {len(nonzero_rows)} states constrain rates; analytical
               inversion requires a square system.")
   ```

### 3.5 Edge case: zero rates

If `len(mb.name_modeled_rates) == 0` the runtime returns `jnp.zeros(0)`
without attempting any solve.

## 4. Build-time pipeline (executed once)

1. Validate inputs: `process.biological_ode is not None`,
   `isinstance(mb, RhsOde)`. Build `state_splines` if missing.
2. Collect orderings: `state_names = mb.name_modeled_RMCs + mb.name_modeled_PVs`,
   `mb.name_controlled_PVs`, `mb.name_modeled_rates`,
   `mb.name_modeled_algebraic`. These are static under JIT.
3. Build a sympy symbol table covering states, controlled PVs, algebraic
   names, and rates. `sympify` every `algebraic` and `derivatives` expression
   under that table.
4. Topo-sort `algebraic` (already done by `get_process_ordering` and stored
   in `mb.name_modeled_algebraic`); inline each algebraic expression into
   all later expressions and into every per-state derivative; `sympy.expand`
   the result.
5. For each per-state expression, compute the row of the rate Jacobian
   `A_row` and the rate-zero intercept `b0`; check linearity (Section 3.2).
6. Lambdify each `A[i,k]` and each `b0[i]` over the flat argument vector

   ```
   args = concat(state_values, ctrl_pv_values)
   ```

   using `_lambdify_with_array_arg` with `modules="jax"`. The wrapper
   accepts a single `args` tensor (positional `*args` is unsafe under
   `jax.jit`).
7. Decide diagonal vs. dense solve and freeze the `nonzero_rows` index
   array. Pre-pull each reactor spline's `c_star_spline.derivative()` and
   `(adf_times, adf_values)` arrays; pre-pull each PV spline derivative.
8. Cache the `ControlSplines` PV slice (entries after the FVC|SVC blocks,
   length `len(mb.name_controlled_PVs)`) for use at runtime.

## 5. Runtime pipeline (`rates_func(t)`)

Per-call, all loops over names/indices are Python-static (the lengths and
keys are known at build time); only `t` and the spline data are traced.

1. **State concentrations.** Evaluate each reactor spline and each PV
   spline at `t`; concatenate to `c_state ∈ R^{n_state}`.
2. **Biological `dc/dt`.** Per Section 3.3 — `c*`-domain derivative divided
   by `adf(t)` for reactor states with a `BacktransformSpline`, plain
   spline derivative otherwise.
3. **Controlled PVs.** `u = ctrl(t); ctrl_pv = u[n_FVCs+n_SVCs:]`.
4. **Args & intercepts.** `args = concat(c_state, ctrl_pv); b0_vec[i] =
   b0_funcs[i](args); b = bio_dc - b0_vec`.
5. **Solve.** Diagonal fast path or `jnp.linalg.solve` over `nonzero_rows`,
   per Section 3.4.
6. **Return** `rates ∈ R^{len(mb.name_modeled_rates)}`, ordered as
   `mb.name_modeled_rates`.

## 6. Failure modes (build-time `ValueError`)

| condition | message |
|---|---|
| `process.biological_ode is None` | requires biological_ode to be set |
| `mb` not `RhsOde` | requires RhsOde from `build_rhs_ode` |
| derivative non-linear in rates | "biological_ode.derivatives[s] is non-linear in rates" |
| `n_rates != len(nonzero_rows)` and not diagonal | "analytical inversion requires a square system" |
| cyclic `algebraic` | from `_topo_sort_algebraic` |

## 7. Differences vs. the previous implementation

The previous inversion path is [`build_q_func`](../bp_format/mechanistic.py#L1296)
plus its wrapper [`build_rates_func`](../bp_format/mechanistic.py#L1811).
That path is still in the codebase and still operates on the
auto-generated `RhsOde` (the `q · biomass + r + feed` form). The
analytical path is a parallel inversion specialized for the user-defined
RHS branch.

| aspect | `build_q_func` / `build_rates_func` (auto path) | `build_rates_func_analytical` (user-defined path) |
|---|---|---|
| RHS form | hard-coded `dc/dt = q·biomass + r + feed_term` for every reactor state | arbitrary user-supplied expressions, must be linear in declared rates; mass balance (e.g. intracellular accumulation) must be encoded in the expressions themselves |
| Rate-vector dimension | `q.shape == (n_reactor_states,)` — one specific rate per reactor component | `rates.shape == (rate_size,)` — set by `len(biological_ode.rates)`; independent of state count |
| Rate semantics | always *biomass-specific* | abstract user-declared symbols; no fixed biological meaning |
| State scope of inversion | reactor-component states only; PV states get `r_pv` from spline derivatives in `build_rates_func` | all non-volume states (reactor + PV); a rate that only appears in PV derivatives is still recoverable |
| Feed / dilution handling | reconstructs `V(t)` from `V0` + cumulative-volume splines + discrete events; subtracts `feed_term = Σ_k (f_k/V)·(C_in_k - c)` in real space | uses pseudo-batch coordinates: `dc/dt_biol = (dc*/dt) / adf(t)`; the `c*` transform absorbs feed, dilution, sampling, and `dV` exactly — no `V`, `Cin`, `u_flow` reconstruction inside the inversion |
| Volume / discrete-event plumbing | `extract_discrete_events`, `cum_splines_ctrl`, `cum_splines_mod`, `_batch_splines`, `ev_dV_cum`, `searchsorted` | none — handled by the `BacktransformSpline` upstream |
| `q` vs `r` partitioning | explicit `q_state_indices` / `r_state_indices` / `r_func` API with overlap-only-with-`r_func` rules | n/a — biological vs. physical split is encoded in the `biological_ode` block; everything outside that block is physical and added by bp-format on top |
| Linearity assumption | implicit (`q · biomass` is linear by construction) | verified symbolically (`sympy.diff` / `sympy.expand` residual check) and rejected at build time if violated |
| Solve | per-row scalar division: `q_i = (dc/dt - feed_term - r_overlap) / biomass` | diagonal fast path (per-row scalar) or `jnp.linalg.solve(A, b)` over non-zero rows |
| Symbolic toolchain | none; pure numerical formulas | sympy: `sympify`, `_topo_sort_algebraic`, `diff`, `expand`, `subs`, `lambdify(modules="jax")` |
| Dependence on `ctrl` | only through downstream callers (the inversion itself ignores `ctrl`) | required: controlled-PV values are bound into `args` via the `[n_FVCs+n_SVCs:]` slice of `ctrl(t)` |
| Reactor-spline contract | calls `state_splines[s](t)` and `state_splines[s].derivative()(t)` directly in real space | requires `BacktransformSpline` (with `c_star_spline`, `adf_times`, `adf_values`) for the `c*`-domain inversion; gracefully falls back to identity transform if absent (correct only when `adf ≡ 1`) |
| Output | wrapped by `build_rates_func` into `(q, r)` for the integration callback signature `rates_func(t, state, controls)` | returns rates only; signature is `rates_func(t)`. Forward integration consuming this rate vector lives in `bp-train` (bp-format does not ship its own integrator). |
| Active-biomass handling | not modelled in the auto path — `q` is divided by `c[biomass]` directly (clamped to `1e-6`) | not handled here; the user expresses `X_active = biomass − intracellular` as an `algebraic` entry and writes it into the relevant per-state expressions explicitly |

### Inputs newly required

- A validated `biological_ode` block (`algebraic`, `rates`, `derivatives`)
  with every dynamic state present and every expression sympy-parseable
  over the typed symbol table.
- Reactor-component splines built as `BacktransformSpline` from the stored
  process-level `pseudobatch_transform` when c*-domain concentrations are
  present.
- Linearity of every `derivatives[s]` in the declared rate symbols.
- A square inversion system: `n_rates` rate symbols matched by `n_rates`
  states whose derivatives depend on at least one rate.
- A `ControlSplines` instance whose `name_controlled_PVs` align with
  `mb.name_controlled_PVs`.

### Inputs newly *not* required

- `q_state_indices` / `r_state_indices` / `r_func` partitioning.
- An `r_func`-style external physical-rate callback (physical contributions
  are added by bp-format from `VolumeChange` data outside this function).
- Reconstruction of `V(t)`, `Cin`, `u_flow`, or discrete-event volume
  jumps inside the inversion — the `c*`-coordinate input absorbs them.

## 8. JIT / autodiff notes

- All Python-level iteration is over static names/indices fixed at build
  time; only `t` and array data are traced.
- `_lambdify_with_array_arg` wraps `sympy.lambdify(..., modules="jax")` so
  the produced callables consume a single concatenated `args` tensor and
  are safe under `jax.jit` / `eqx.filter_jit`.
- `nonzero_rows` is materialized as a `jnp.array` once at build time and
  used as a static gather index at runtime.
- `adf` is clamped at `1e-12` to keep the division differentiable through
  zero-dilution edge cases.

## 9. Provenance

The function lands together with the `biological_ode` data-model block in
commit `c7419b4` ("add user-defined biological ODE block and fix
intracellular mass balance"). The dual-path equivalence tests against the

## 10. Legacy auto-path inversion (deleted in P3 refactor)

The P3 refactor removed three spline-based rate-inversion helpers along with
the auto-RHS dispatch they targeted. The functionality is captured here so the
forward-going `build_rates_func_analytical` implementer has a complete
reference.

### 10.1 Removed symbols

- `build_q_func(process, ctrl, rhs_ode, state_splines, *, conc_splines, q_state_indices, r_state_indices, r_func) -> Callable[[float], jnp.ndarray]`
- `build_rates_func(process, ctrl, rhs_ode, state_splines, *, conc_splines, q_state_indices, r_state_indices, r_func) -> Callable[[float, state, controls], tuple[jnp.ndarray, jnp.ndarray]]`
- `estimate_specific_rates(process, ctrl, rhs_ode, state_splines, t_eval, *, conc_splines, q_state_indices, r_state_indices, r_func) -> jnp.ndarray`
- `integrate_process_pseudospace(process, ctrl, rhs_ode, rates_func, t_eval, *, state_splines, conc_splines, rtol, atol, use_jump_ts, max_steps) -> dict`

### 10.2 Mathematical model

The core math was a per-row inversion of the auto-RHS mass balance,

```
q_i(t) = (dc_i/dt - feed_term_i - r_overlap_i) / max(c_biomass(t), 1e-6)
```

for `i ∈ q_state_indices`, with feed term

```
feed_term = Σ_k (f_k / V) · (C_{in,k} - c)
```

summed over controlled and modeled flows. `_MIN_ACTIVE_BIOMASS = 1e-6` clamped
the denominator. States outside `q_state_indices` produced `q_i = 0` (mask).
PV states produced `r_pv = spline.derivative()(t)`.

### 10.3 Q/R partitioning rules

- Default (`q_state_indices is None and r_state_indices is None and r_func is None`):
  all reactor states are q-states, `r_state_indices = []`, no overlap subtraction.
- If `r_func is not None`, both index sets must be supplied explicitly so the
  inversion knows which reactor states to treat physically.
- Overlap (`set(q_state_indices) ∩ set(r_state_indices) != ∅`) is allowed
  only when `r_func` is provided so overlap r can be subtracted before
  solving for q.
- The union of `q_state_indices ∪ r_state_indices` had to cover all reactor
  states.

### 10.4 `build_rates_func` packaging

The wrapper concatenated `q` (from `build_q_func`) with an additive physical
rate vector `r` to satisfy the legacy `(q, r)`-tuple integration callback:

- `q.shape == (n_reactor,)`
- `r.shape == (n_non_volume,)`; first `n_reactor` entries align to reactor
  components, remaining entries align to PV states
- `r_reactor` portion: zeros if `r_func is None`; otherwise `r_func(t)[:n_reactor]`
- `r_pv` portion: PV state-spline derivatives if `r_func is None`; otherwise
  `r_func(t)[n_reactor:]`

### 10.5 `estimate_specific_rates` packaging

A thin, JIT-compiled wrapper around `build_q_func`:

- Built `q_func`, JIT-compiled with `eqx.filter_jit`, vmapped over `t_eval`.
- Returned `(len(t_eval), n_reactor)` array of recovered specific rates.

### 10.6 Volume / discrete-event plumbing

`build_q_func` reconstructed `V(t)` analytically:

- Cumulative-volume splines per controlled and modeled flow, sourced from
  `process.volume.volume_changes[fn].values`.
- All flows batched into a single owned `PPoly` via `_batch_splines`.
- Discrete events extracted via `extract_discrete_events(process, rhs_ode)`,
  sorted by time, cumulative `dV` precomputed.
- `V(t) = V0 + Σ batched_vol(t) + Σ_{events ≤ t} dV`, with `V0` clamped via
  `_require_reactor_volume_above_threshold`.

### 10.7 JIT contract

`q_func(t)` was `eqx.filter_jit`-compatible. All Python iteration over
state/flow names was build-time static; only `t` and array data were traced.

### 10.8 `integrate_process_pseudospace`

A `c*`-domain integrator that ran a single-pass `diffeqsolve` with state
living in pseudo-batch coordinates. It encoded the same auto-RHS shape
(`q · biomass + feed_term`) inside its segment RHS and was incompatible with
arbitrary user-defined `BiologicalOde` expressions. Used in tests for
trajectory-recovery sanity checks (`integrate_process` vs.
`integrate_process_pseudospace`) and in verification scripts under
`examples/12_martens_expanded/03_verification_pseudobatch/`.

### 10.9 Test coverage that exercised these paths

- `tests/test_mechanistic.py::TestEstimateSpecificRates` — asymptotic
  correctness on synthetic processes with known q.
- `tests/test_mechanistic.py::test_build_rates_func_*` — shape and
  `(q, r)` tuple structure.
- `tests/test_mechanistic.py::test_pseudospace_*` — pseudospace integrator
  cross-checks against the segmented `integrate_process` path.
- `tests/test_mechanistic_integration_accuracy.py` — full deleted file;
  detailed contract preserved in [Section 10.11](#1011-deleted-integration-accuracy-test-suite-detailed-contract)
  below.
- Verification scripts under `examples/12_martens_expanded/{02,03}_verification/`,
  `examples/13_volume_integration/03_verification/`, and
  `examples/14_simulation_intracellular/02_verification/`.

### 10.10 Migration directive

Replace with `build_rates_func_analytical` per Sections 1-8 of this doc. The
new path operates in pseudo-batch (`c*`) coordinates, requires the
`biological_ode` block (always present after the P3 refactor), is linear in
declared rates, and lives at the user-defined-RHS shape rather than the auto
shape. The old API's index-partitioning knobs (`q_state_indices`,
`r_state_indices`, `r_func`) collapse into the symbolic `algebraic` /
`derivatives` block, which encodes biological vs. physical splits explicitly
inside the user-supplied expressions.

### 10.11 Deleted integration-accuracy test suite (detailed contract)

The file `tests/test_mechanistic_integration_accuracy.py` was the
end-to-end regression guard for the auto-RHS rate-inversion +
forward-integration pipeline. It is deleted in the P3 refactor because
every test in it was structurally tied to the deleted helpers. The
contract below defines the *what to re-implement against
`build_rates_func_analytical`* checklist; the new file should be added
back at the same path, parameterised over the same fixtures, with the
same per-species and combined-RMS bounds.

#### 10.11.1 Pipeline harness — `_run_mechanistic_pipeline(fixture_dir, *, mutator=None)`

For each fixture directory, the helper performed:

1. Load via `bp_format.serialization.load_dataset_json(fixture_dir / "data.json")`.
2. Pull the single (case-study, process) pair out of the dataset.
3. If `mutator is not None`, invoke `mutator(process)` (intracellular
   variants attached a custom `BiologicalOde` to a previously
   intracellular-flagged fixture).
4. Snapshot the original measured `(times, values)` for every
   reactor-medium component whose concentration is a `TimeSeries`. These
   are the *ground truth* the integrator output is benchmarked against.
5. Build pseudobatch transforms for those species. Keep each reactor
   component's real measured `concentration` intact and store the matching
   pseudobatch c* carrier in `component.c_star_concentration`; downstream
   state-spline construction uses the process-level transform bundle to
   backtransform c* to real concentration when needed.
6. Build `ctrl = bpm.get_control_splines(process)`,
   `rhs_ode = bpm.build_rhs_ode(process)`,
   `state_splines = bpm.build_state_splines(process, rhs_ode)`.
7. Extract discrete events to size the q-inversion grid:
   `n_q_grid = max(500, 20 * n_events)`,
   `t_eval_q = np.linspace(t_start, t_end, n_q_grid)`.
8. Estimate q on `t_eval_q` (was: `bpm.estimate_specific_rates(...)` →
   `(len(t_eval_q), n_reactor)`) and fit a single cubic
   owned `PPoly`/cubic spline `q_spline` over `t_eval_q`.
9. Wrap the spline as a runtime `rates_func` (was: `_wrap_q_as_rates(rhs_ode, q_func)`
   producing `(q(t), jnp.zeros(rhs_ode.r_size))`). With the new flat
   protocol the wrapper must produce a flat `(rate_size,)` array aligned
   with `rhs_ode.rate_names`.
10. Forward-integrate on a coarser eval grid:
    `t_eval_int = np.linspace(t_start, t_end, 200)` →
    `bpm.integrate_process(process, ctrl, rhs_ode, rates_func, t_eval_int)`.
11. For each reactor-component state, interpolate the integrator's
    output onto the *original* observation timestamps and compute
    `nrmse = sqrt(mean((v_pred - v_meas) ** 2)) / (v_meas.max() - v_meas.min())`,
    falling back to `0.0` when the range is `≤ 1e-12`.
12. Return a metrics dict:
    ```
    {
      "species": {sp: {"rmse": ..., "range": ..., "nrmse": ...}, ...},
      "rms":     sqrt(mean(per_species_nrmse ** 2)),
      "n_events": n_events,
    }
    ```

#### 10.11.2 Per-species assertion — `_assert_per_species(metrics, *, tol)`

Take the species with the *worst* nRMSE; assert it is below `tol`.
Failure message must include the offending species name, observed nRMSE,
the bound, and the full per-species metrics dict so a regression is
diagnosable from the test output alone.

#### 10.11.3 Fixture matrix and tolerance bounds

| Fixture (under `tests/fixtures/`) | Test name(s) | Per-species `tol` | RMS `tol_rms` |
|---|---|---|---|
| `martens_2025_f_single` | `test_martens_2025_f_mechanistic_integration_accuracy` | `0.01` | `5e-3` (parameterised RMS test) |
| `martens_expanded_single` | `test_martens_expanded_mechanistic_integration_accuracy` | `0.01` | `5e-3` (parameterised RMS test) |

Each fixture also runs through the *intracellular variant* by passing
`mutator=_attach_intracellular_biological_ode` (see 10.11.5 below) for
two further tests:

| Test name | `tol` | `tol_rms` |
|---|---|---|
| `test_mechanistic_integration_with_intracellular_product[<fixture>]` | `0.01` | — |
| `test_mechanistic_rms_summary_with_intracellular_product[<fixture>-0.005]` | — | `5e-3` |

The non-intracellular RMS variant is `test_mechanistic_rms_summary[<fixture>-0.005]`.

The bounds are loose enough to absorb floating-point and spline-resampling
noise, tight enough to catch any systematic mechanistic regression. The
historical signal that motivated this suite was a regression where
`BacktransformSpline.derivative()` got the quotient rule wrong and
pushed worst-species nRMSE on `kittler_2022` from <0.001 to **0.462**.

#### 10.11.4 Dual-path equivalence test (drops in the new world)

The deleted file also contained `test_dual_path_dcdt_equivalence[*]` and
`test_dual_path_dcdt_equivalence_with_intracellular_product[*]`. Those
asserted that an auto-built `RhsOde` and a hand-written
`UserDefinedRhsOde` produced identical `dc/dt` at randomly sampled
`(c, rates, u_flow, f_modeled)` inputs:

```python
def _make_equivalent_biological_ode(rhs_ode) -> BiologicalOde:
    state_names = list(rhs_ode.reactor_component_state_names)
    biomass_name = state_names[0]   # was: state_names[rhs_ode.biomass_idx]
    rates = {f"q_{n}": (None, None) for n in state_names}
    derivatives = {n: f"q_{n} * {biomass_name}" for n in state_names}
    for pv_name in rhs_ode.process_variable_state_names:
        derivatives[pv_name] = "0"
    return BiologicalOde(algebraic={}, rates=rates, derivatives=derivatives)
```

After P3, the auto path *is* the user-defined path — `BioProcess.__post_init__`
auto-populates exactly this kind of block. The dual-path equivalence
assertion is therefore tautological and **not** part of the
re-implemented suite. The intracellular variant is also redundant: it is
already covered by the integration-accuracy tests above when the
intracellular `BiologicalOde` is attached via `mutator`.

#### 10.11.5 Intracellular helper — `_attach_intracellular_biological_ode(process)`

The fixtures `martens_2025_f_single` and `martens_expanded_single` model
intracellular accumulation by attaching a `BiologicalOde` block:

```python
def _attach_intracellular_biological_ode(process):
    state_names = list(process.reactor_medium.components.keys())
    biomass_name = next(n for n in state_names if n.strip().lower() == "biomass")
    other_names = [n for n in state_names if n != biomass_name]
    rates = {f"q_{biomass_name}": (None, None)}
    for n in other_names:
        rates[f"q_{n}"] = (None, None)
    derivatives = {
        biomass_name: f"q_{biomass_name} * X_active + q_product * X_active",
    }
    for n in other_names:
        derivatives[n] = f"q_{n} * X_active"
    for pv_name, pv in process.process_variables.items():
        if not pv.is_controlled:
            derivatives[pv_name] = "0"
    process.biological_ode = BiologicalOde(
        algebraic={"X_active": f"{biomass_name} - product"},
        rates=rates,
        derivatives=derivatives,
    )
```

The re-implemented suite must keep this helper verbatim; it is what makes
the intracellular branch testable without resurrecting the deleted flag.

#### 10.11.6 What changes when `build_rates_func_analytical` lands

- The q-inversion step (`bpm.estimate_specific_rates(process, ctrl, rhs_ode, state_splines, t_eval_q)`)
  becomes `rates_analytical = build_rates_func_analytical(process, ctrl, rhs_ode, state_splines)` — a single callable that takes `t` and returns the flat rate vector aligned with `rhs_ode.rate_names`.
- The wrapper `_wrap_q_as_rates` disappears. The wrapper for
  `integrate_process` is the analytical rates_func directly (or a cubic
  resampling of it on `t_eval_q` for stability, mirroring the
  spline-fitted q workflow).
- `metrics["species"]` keying stays in `rhs_ode.reactor_component_state_names`
  order; PV states are not part of the per-species comparison.
- The dual-path equivalence test stays deleted.

The bounds, fixture matrix, and assertion shape carry over unchanged.
